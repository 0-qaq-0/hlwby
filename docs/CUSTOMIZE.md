# 自定义判断类型

这份文档解决一个问题：**怎么把这套判定器用在你自己的场景上** —— 判的不是「八艺」，
而是你的工单队列、你的内容处置尺度、你的意图分类。从字段含义、硬边界、锚点怎么写，
到改完拿什么验证、什么写法会翻车，全部对着代码和实测数字讲。

> 前提认知：**判定逻辑是运行时的数据，不是训练出来的参数。**
> 一个判断类型 = 一段判定问法（`criterion`）+ 每个选项的锚点描述（`labels[].description`）
> + 几条页面示例（`examples[]`）。这些文字在**推理时**才读进 prompt，不写进任何权重。
> 所以改它**不用重训、不用重新下载模型**；用户类型改完保存即生效，连服务都不用重启。

---

## 一、一个判断类型是什么

引擎的输入只有三样：**要判的文本** + **判定问法** + **带描述的选项列表**。
「判断类型」（profile）就是把后两样打包起来的一份数据。

```
一次判定的 prompt（engine.py 的 _messages）
├── system：固定的一句话（DIRECT_SYSTEM_ZH）
└── user：{"evidence": 待判文本, "criterion": 判定问法,
           "options": [{"letter": "A", "description": 锚点1}, ...]}
```

| | 是什么 | 改它要做什么 |
|---|---|---|
| 基座模型（Qwen3.5-2B） | 权重 | 换模型 → `--model`，见 README「换模型」一节 |
| **criterion / 锚点描述 / 页面示例** | **运行时数据** | **改数据 → 保存即生效** |
| 引擎的读出机制（字母槽位 + softmax + 排列平均） | 代码 | 一般不用动 |

这带来两个直接后果，也是「自定义判断类型」这件事成立的原因：

* **同一个模型能判任意多套类型。** 内置的「客服分流」「内容处置」和「八艺」用的是
  同一个 2B 模型、同一份权重，只是 prompt 里的选项列表不同。
* **准确率由锚点决定，不由模型大小决定。** `docs/EVAL.md` 第 4.1 节的对照实验是
  最直接的证据：同一个模型、同一个意思，锚点写成关系式（「当对方辩论时」）会全军覆没，
  写成文本形态（「逐条辩论、分点回击，常见开头是『第一……第二……』」）准确率从
  **50% 跳到 96%**。换锚点比换模型便宜得多。

**用户类型存在 `data/profiles/<id>.json`，内置类型在代码里**（`tiaoyige/labels.py`
的「八艺」+ `tiaoyige/builtin_profiles/*.json`）。两者在接口上长得一样，区别只有两条：
内置的改不了、删不掉（想改就另存为一份新的），以及「八艺」是唯一评测过的那一套。

## 二、一个 profile 有哪些字段

字段定义在 `tiaoyige/profiles.py` 的 `Profile` 数据类里（`Profile` / `to_dict` /
`from_dict`），校验规则在同文件的 `validate()`。

| 字段 | 类型 | 必填 | 干什么用的 |
|---|---|---|---|
| `id` | str | **是** | 类型标识，**同时就是存盘文件名**（`data/profiles/<id>.json`）。见第三节的硬边界 |
| `name` | str | **是** | 显示名，页面和结果里显示。超过 24 字只提示（建议 12 字以内） |
| `summary` | str | 否 | 一句话说明，列表里用（`to_summary()`） |
| `criterion` | str | **是** | 判定问法 —— **模型读的就是这句话**，它和锚点一起进 prompt |
| `labels[]` | list | **是** | 选项列表，2~16 个。见下面的选项字段表 |
| `examples[]` | list | 否 | 页面示例，点一下就能试判。每条 `{"label": 选项id, "text": 例句}` |
| `version` | str | 否 | 锚点版本，默认 `"v1"`。**改了措辞就该改它**，否则「这个数字是哪版测的」说不清 |
| `note` | str | 否 | 备注。内置的两个示例类型在这里写「未评测，别拿它当成绩」 |
| `builtin` | bool | 否 | 内置标记。**保存时会被强制改回 `false`** —— 存下来的一定是用户类型 |
| `evaluated` | bool | 否 | 有没有在干净测试集上评测过。`false` 时 `validate()` 会提示一句 |
| `updated_at` | str | 否 | 保存时由 `ProfileStore.save()` 写成 UTC ISO 时间，不用手填 |
| `schema` | int | 否 | 数据格式版本（`tiaoyige/version.py` 的 `SCHEMA_VERSION`）。保存/导出时写出，读入时忽略 |

`labels[]` 里每一项：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | **是** | 选项标识，就是判定结果里返回的那个值。不能为空、不能重复、不能含空白；超过 6 字会挤（只提示） |
| `description` | **是** | **锚点描述** —— 决定判定结果的那段文字，整份文档第五节都在讲它 |
| `name` | 否 | 显示名，缺省等于 `id` |
| `hint` | 否 | 只给页面看的人话解释（不进 prompt）。不填只提示 |
| `pinyin` | 否 | 拼音，页面用，缺省空串 |
| `accent` | 否 | 概率条配色，缺省 `#6ea8fe` |

### `from_dict()` 是刻意宽松的

`Profile.from_dict()` 的注释写得很直白：这个函数的输入一半来自用户手写的 JSON 和
浏览器里的半成品状态，**报「缺字段」不如先收下来再让 `validate()` 说清楚**。所以：

* 缺的字段补默认值（`version` → `"v1"`、`accent` → `#6ea8fe`、`name` → `id`）；
* 多余的字段直接丢掉；
* `examples[]` 里 `text` 为空的条目被丢掉；
* 导出文件的信封也认 —— `{"profile": {...}}` 会自动拆开。

**真正拦住你的是 `validate()`**，不是 `from_dict()`。

## 三、三条硬边界

这三条不是风格建议，是代码里写死的，越过去直接报错或者行为不对。

### 1. 选项数 2~16

```python
MIN_LABELS = 2
MAX_LABELS = 16   # 上游把选项绑到 A–P 这 16 个单 token 槽位上
```

为什么是 16：引擎把每个选项绑到一个**单 token 的大写字母槽位**（`A`–`P`），
一次前向只读这些槽位上的 logits。字母只有 26 个，上游取到 `P`；
引擎内部还会再校验一次「选项数量必须在 2 到 16 之间」（`engine._readout_many`）。

选项 1 个没有意义，17 个绑不上槽位 —— `validate()` 直接给 error，存不下来。

### 2. `id` 就是文件名

```python
SLUG_RE = re.compile(r"^[a-z0-9][a-z0-9_-]{1,47}$")
```

* 只能用**小写字母、数字、下划线、连字符**，且**以字母或数字开头**；
* 长度 **2~48** 位；
* 存盘路径是 `data/profiles/<id>.json`（`ProfileStore.path_of()` 直接拼 id）。

> **坑：文件名必须和文件里的 `id` 一致。**
> `ProfileStore._load_user()` 只在文件里没写 `id` 时才拿文件名当 id。
> 如果文件叫 `foo.json` 而里面写着 `"id": "bar"`，会出现两种很难查的现象：
> `delete("bar")` 删不掉（删除按文件名 stem 找，返回 `false`），
> 而再存一份 `bar.json` 之后列表里会出现**两个 id 都是 `bar`** 的类型。
> 页面和接口保存的类型不会有这个问题（文件名由 id 生成），手写文件时注意就行。

### 3. `bayi` 是内置只读 id

`bayi` 是「八艺」的 id，权威出处是 `tiaoyige/labels.py`。它**永远在、只读**：

* `save()` 撞上 `bayi` 直接抛 `ProfileError`：「bayi 是内置类型的 id（它永远在，只读），
  换一个，比如 bayi-2」；
* `delete("bayi")` 返回 `false` → 接口回 400「内置类型只读」；
* 就算你手写一个 `data/profiles/bayi.json`，`ProfileStore.list()` 也会跳过它 ——
  用户类型**不能顶掉**内置类型。想改八艺的锚点，另存为 `bayi-2`。

另外，`POST /api/profiles/delete` 只删 `data/profiles/` 里的用户类型，
内置目录 `tiaoyige/builtin_profiles/` 和 `labels.py` 都不在它的射程内。

## 四、从零写一套

三条路，终点完全一样：`data/profiles/<id>.json`。页面上的判断类型编辑器**没有第二套逻辑**
（`server.py` 模块开头就是这么写的），它调的就是下面这些接口。

> 如果你的页面版本里还没有「判断类型」入口，直接用 4.2 或 4.3 —— 三条路等价。

### 4.1 在页面上新建（推荐）

页面上的「词表」标签页：新建 / 选一套 → 改锚点 → 保存，**边改边校验**，
改完不用重启服务，判定页立刻就是新词表。它背后打两个接口：

1. 每改几下 → `POST /api/profiles/validate`：拿回 `issues[]`、`error_count`、`warning_count`、
   `stats`。**只校验、不保存**，所以可以放心乱改；
2. 点保存 → `POST /api/profiles`：`error` 级别的规则会拦住保存（返回 400 + `issues[]`），
   `warning` 只回显不拦。

想覆盖已有的同 id 类型，请求体里加 `"overwrite": true`，否则回 400
「已经存在同 id 的类型「xxx」，确认要覆盖再重试。」

### 4.2 直接写 `data/profiles/<id>.json`

最小完整例子 —— 下面这份**真的过了校验**（验证命令和输出见 4.4）：

```json
{
  "id": "code-review",
  "name": "评审意见",
  "summary": "把一条 PR 评论分成阻塞、建议、提问三类 —— 文档里的最小示例",
  "criterion": "下面这条代码评审评论，最该被归到哪一类？请选出最贴切的那一个。",
  "version": "v1",
  "note": "文档里的最小示例，未在干净测试集上评测过，别拿它当成绩。",
  "labels": [
    {
      "id": "阻塞",
      "name": "阻塞",
      "pinyin": "zusai",
      "description": "这段话在说「不改就不能合」：指出会出错、会丢数据、有安全问题，要求必须改。例：「这里没判空，上线会 NPE，必须改」「这个循环会死锁，先别合」「密钥硬编码进仓库了，赶紧撤掉」。",
      "hint": "不改就不能合。",
      "accent": "#dc2626"
    },
    {
      "id": "建议",
      "name": "建议",
      "pinyin": "jianyi",
      "description": "这段话在提一个可改可不改的改进：命名、拆分、注释、性能，加不加「我觉得」都算。例：「这个函数有点长了，要不要拆一下」「变量名可以叫 retry_count 更清楚」「这里补一行注释会好懂些」。",
      "hint": "可改可不改的改进。",
      "accent": "#2563eb"
    },
    {
      "id": "提问",
      "name": "提问",
      "pinyin": "tiwen",
      "description": "这段话在问作者为什么这么写、某段逻辑是什么意思、有没有考虑过另一种情况。例：「这里为什么不用现成的工具函数」「这个分支什么时候会走到」「如果并发进来会怎么样」。",
      "hint": "在问，不是在要求改。",
      "accent": "#0f766e"
    }
  ],
  "examples": [
    { "label": "阻塞", "text": "这个接口没做鉴权，谁都能拿到别人的订单，先别合。" },
    { "label": "建议", "text": "这个判断抽成一个小函数可能更好读一点。" },
    { "label": "提问", "text": "超时定 3 秒是压测出来的吗？" }
  ]
}
```

放好之后 `GET /api/profiles/code-review` 就能读到它，判定时 `"profile": "code-review"`。

三个细节值得注意，都是刻意设计的：

* **锚点里给了例句，而且是「」引号包起来的具体句子** —— 见第五节第 2 条；
* **页面示例不是锚点例句的复制品** —— 见第五节第 6 条；
* `note` 里明说「未评测」。`evaluated: false` 时页面会显示「未评测」，
  `validate()` 也会提示一句：**页面上那个准确率数字是「八艺」的，不是你的。**

### 4.3 导入导出文件

* **导出**：`GET /api/profiles/<id>/export` 直接返回一份**裸 profile JSON**
  （不是 `{"ok": ...}` 信封），带 `Content-Disposition: attachment; filename="<id>.json"`。
  浏览器里点一下就是下载。
* **导入**：`POST /api/profiles/import`，请求体可以是导出文件本身，也可以是
  `{"profile": {...}}`，加 `"overwrite": true` 覆盖同 id。
  没有 `id` 的文件会被拒：「导入的文件里没有 id」。
* **导出的内置类型可以直接导入** —— 导出文件里带着 `"builtin": true`，
  但 `save()` 会把它强制改回 `false`，否则「导入一份内置类型的副本」永远失败。

### 4.4 验证你写的那份文件

命令行一把梭（`--only` 只查一套，`--strict` 把 warning 也算失败）：

```powershell
$py = ".\.venv\Scripts\python.exe"
& $py scripts\profiles_check.py --only code-review
```

这份例子的实际输出：

```
===== [code-review] 评审意见（用户·未评测）=====
  选项 3 个：阻塞 建议 提问
  问法：下面这条代码评审评论，最该被归到哪一类？请选出最贴切的那一个。
  锚点 264 字（80~96），例句约 11 条，页面示例 3 条
  提示  [evaluated] 这套类型还没有在干净测试集上评测过。页面上的准确率数字是「八艺」的，不要拿它当这套类型的成绩。
```

**error 0 条，warning 1 条**，唯一的 warning 就是「还没评测过」—— 那是事实，不是毛病。

## 五、写锚点：六条实测规则

这是这份文档的核心。六条全部来自 `docs/EVAL.md`（每个数字都能在那份文档里找到出处），
`validate()` 把其中大部分变成了**可执行的检查**。

| # | 规则 | 实测数字 | 出处 | `validate()` |
|---|---|---|---|---|
| 1 | 描述「文本长什么样」，不是「说话人在干什么」 | 关系式 50% → 文本形态 96% | EVAL.md 4.1 | 只查 `criterion` |
| 2 | 给例句，别写抽象定义 | 多锚点 96% vs 长抽象定义 23%；只给关键词 1/10 | EVAL.md 4.2 | warning |
| 3 | 要示范，不要解释（别在描述里提别的选项名） | 加「区别：这不是 X」后 83% → 73% | EVAL.md 4.3 | warning |
| 4 | 别写泛化的形状描述 | 删掉「一段不长不短的普通论述」73.1% → 80.8% | EVAL.md 3.3 / 4.4 | warning |
| 5 | 别为了长度均衡去删例句 | 删了几条凑长度，96% → 88% | EVAL.md 4.5 | 只提示长度极差 |
| 6 | 页面示例不能是锚点例句的复制品 | 自问自答；24 条「干净集」里 14 条在抄锚点 | EVAL.md 3.2 / 4.6 | warning |

### 1. 描述「文本长什么样」，不是「说话人在干什么」

**这条最重要，也最反直觉。** 「八艺」这套定义本身是关系式的（「当对方辩论时，回急」），
照字面写锚点（「对方在跟你辩论，或者开始细致地解说……」）的结果是**全部塌缩到「赢」**，
准确率只有 **50%**。

`docs/EVAL.md` 4.1 的对照实验把这件事钉死了：同一个意思写成格言腔和大白话 ——

| 形式 | 文本 | 期望 | 判成 |
|---|---|---|---|
| 格言腔 | 人最大的敌人，从来都是自己。 | 赢 | **赢 99%** ✅ |
| 大白话 | 我觉得人最大的问题就是过不了自己那关。 | 典 | **赢 91%** ❌ |

大白话版本完全不是格言，却被判成「赢」。说明模型没在按定义判 ——
**2B 模型做的是表面形式匹配，不是关系推理。**

**修法**：把锚点写成**这段文本的表面形态**。

| 别写 | 改写成 |
|---|---|
| 「对方在辩论、分点论述」 | 「这段话在逐条辩论、分点回击，读起来像在跟人抬杠。常见的开头是『第一……第二……第三』『我们先明确一个前提』」 |
| 「自己说了一句金句」 | 「这段话是一句自我感觉良好的金句：对仗、押韵、格言腔，『不是……而是……』『从来都是』这种腔调」 |
| 「对方敷衍认输」 | 「这段话只有一句敷衍的附和或认输，非常短，没有任何实质内容」 |

改完 **50% → 79% → 96%**。

> `validate()` 只在 `criterion` 上查关系式说法（`RELATIONAL_HINTS`：`当对方` /
> `如果对方` / `说话人` / `对方正在` / `他在试图`），命中就 warning。
> **它查不到锚点描述里的关系式写法** —— 那部分只能自己盯。
> 想看失败长什么样，跑 `scripts\experiment.py --variants relational`。

### 2. 给例句，别写抽象定义

| 写法 | 结果 |
|---|---:|
| 长描述（3~4 句抽象定义） | 23% |
| 只给关键词 | 1/10 |
| **多锚点例句** | **当前方案（96%）** |

抽象定义要求概念推理，例句只要求模式匹配 —— 后者才是 2B 模型擅长的事。
`labels.py` 里每个字的 `description` 都是「一句形态描述 + 几条例句」的结构
（八段加起来 48 条例句，单段 4~9 条），直接照这个形状写就行。

`validate()` 的判断方式是数引号：描述里成对引号片段少于 2 个、且不含「例：」，
就给 warning「要示范，不要解释」。

### 3. 要示范，不要解释

诊断出模型老把「内容里有人在放弃」读成别的词，于是在每段描述后加了
「区别：这不是 X，那是 Y」。**结果从 83% 掉到 73%。**

原因：描述里提到别的选项名，会把概率质量**漏给那些选项** —— 十段里八段都写了同一个
选项名，那个选项就被反复激活成了吸铁石。

`validate()` 会检查描述里有没有提到别的选项，但**只认明确的引用**，避免误报：

* 被引号包起来的：`「典」`；
* 「不是 X / 区别于 X / 不同于 X / 而不是 X / 并非 X」这种否定式；
* 两个汉字以上的选项 id 直接子串匹配（`阻塞` 这种不太可能是别的词的偶然片段）。

> 为什么单字 id 要特殊对待：选项 id 常常只有一个汉字（「典」），而「典型」「孝道」
> 这类词里也会出现同一个字 —— 直接子串匹配会把正常描述全判成违规。

### 4. 别写泛化的形状描述

这是本项目第二贵的教训。「典」的锚点里原来有一句
**「一段不长不短的普通论述」**，它几乎对所有中文评论都成立 ——
不是判别特征，是**吸铁石**。当时 14 个错例里 11 个判成了「典」。

`scripts/anchor_tune.py` 只改这一段措辞、其余七个字不动，做了剂量反应：

| 「典」的描述 | 准确率 | 判成「典」的错例 |
|---|---:|---:|
| 换成**更泛**的说法 | 69.2% | **15** |
| 原来（带那句） | 73.1% | **10** |
| **只删掉那句** | **80.8%** | **3** |
| 再窄一档（只讲「解释成因/下结论」） | 76.9% | 3 |

**单调关系是这件事最有力的证据**：描述越泛，吸得越狠。
单看「73.1% → 80.8%」只是 4 条，落在噪声范围内；但「越泛 → 吸得越多」这个方向
不可能由噪声产生。所以采用了「只删掉那句」这一档，**+7.7 个百分点**。

推广成一句话：**锚点里的每一句话都应该是判别特征。** 如果一句话对「不属于这个词」
的样本也成立，它就在偷概率。

`validate()` 内置了 14 个泛化短语（`GENERIC_PHRASES`：`不长不短`、`普通的论述`、
`一般的评论`、`大多数评论`、`不管什么`、`任何一段`……），命中就 warning。
它抓不全 —— 自己按上面那条原则复查。

### 5. 别为了长度均衡去删例句

`validate()` 会提示锚点字数极差（`LENGTH_SPREAD_SOFT_LIMIT = 70`），
但那条提示里就写着答案：**别为了压这个去删例句。**

EVAL.md 4.5 记着：一度为了把极差压到阈值内删了几条锚点例句，**准确率立刻从 96% 掉到 88%**，
恢复例句后回到 96%。长度失衡只是略微放大位置偏置（而排列平均已经在压它），
**锚点数量才是准确率的主要来源**。所以那条阈值是**软警告**。

「八艺」自己就没满足这条：锚点 99~241 字，极差 142 —— 它仍然是唯一评测过的那一套。

### 6. 页面示例不能是锚点例句的复制品

页面示例是**给人看的演示**，不是测试集。但它同样不能抄锚点 —— 那是**自问自答**：
prompt 里刚念过的句子，模型当然判得对，这个「必对」零信息量。

`docs/EVAL.md` 4.6 记了两次翻车：页面示例一度只判对 **6/8**（挑的样本不够典型），
换成典型样本后 **8/8** —— 但这个 8/8 一度也是假的，`scripts/leak_check.py` 发现两条示例
直接抄了锚点（重合度 **1.00** 和 **0.27**，后者等于把锚点例句改了两个字）。
两处都换掉之后，8/8 才是真的。

`validate()` 用的是和 `leak_check.py` 完全同一份实现（`tiaoyige/textcheck.py`），
对每条页面示例算它和**最像的那个锚点**的字面重合度：

| 重合度 | 判定 | 含义 |
|---:|---|---|
| ≥ 0.30 | LEAK | 基本能在锚点里逐字找到，必须换 |
| ≥ 0.15 | warn | 可疑，人工看一眼是不是同一句话改了标点 |

> 度量方式：两边只留中英文数字（去掉标点空白），比字符 8-gram 的集合重合率，
> 分母取**较短一侧** —— 否则一句 20 字的示例对上一段 120 字的锚点，重合率会被稀释成 0。
> 短句（归一化后不足 5 字）直接放过，宁可不报也不要误报。

## 六、`validate()` 会报什么

规则全部在 `tiaoyige/profiles.py` 的 `validate()` 里，页面编辑器、`profiles_check.py`、
`POST /api/profiles/validate` 调的都是同一份实现。

### error —— 拦住保存

| 字段 | 触发条件 |
|---|---|
| `id` | 不符合 `^[a-z0-9][a-z0-9_-]{1,47}$`（2~48 位小写字母/数字/下划线/连字符，首字符是字母或数字） |
| `name` | 为空 |
| `criterion` | 为空 —— 「模型读的就是这句话」 |
| `labels` | 选项数不在 2~16 |
| `labels` | 选项 id 有重复 |
| `labels[i]` | 选项 id 为空 |
| `labels[i]` | 选项 id 里有空白字符 |
| `labels[i]` | 该选项没有锚点描述 |
| `examples[i]` | 示例指向了不存在的选项 |

### warning —— 只提示

| 字段 | 触发条件 | 背后的实测依据 |
|---|---|---|
| `name` | 显示名超过 24 字 | 页面上会截断 |
| `criterion` | 超过 200 字 | 太长会稀释锚点 |
| `criterion` | 出现关系式说法（`当对方`/`说话人`…） | EVAL.md 4.1：关系式写法 50% |
| `labels[i]` | 选项 id 超过 6 字 | 页面上会挤 |
| `labels[i]` | 描述里几乎没有例句（引号片段 < 2 且无「例：」） | EVAL.md 4.2：96% vs 23% |
| `labels[i]` | 描述里有泛化短语（14 个内置） | EVAL.md 3.3 / 4.4：+7.7 个百分点 |
| `labels[i]` | 描述里提到了别的选项名 | EVAL.md 4.3：83% → 73% |
| `labels[i]` | 没填 `hint` | 页面上判定结果会少一句解释 |
| `examples` | 一条页面示例都没有 | 第一次打开页面不知道从哪下手 |
| `examples` | 有选项没被示例覆盖 | 用户看不到那个选项的典型样本 |
| `examples[i]` | 这条示例和前面某条重复 | —— |
| `examples[i]` | 示例与锚点字面重合 ≥ 0.30（或 ≥ 0.15 可疑） | EVAL.md 3.2 / 4.6：自问自答 |
| `labels` | 锚点字数极差 > 70 | EVAL.md 4.5：**别为了压它删例句** |
| `evaluated` | 还没在干净测试集上评测过 | 页面上的数字是「八艺」的 |

### 保存层还有两条 error（不在 `validate()` 里）

| 触发条件 | 报什么 |
|---|---|
| `id` 是 `bayi` | 「bayi 是内置类型的 id（它永远在，只读），换一个，比如 bayi-2」 |
| 同 id 已存在且没给 `overwrite` | 「已经存在同 id 的类型「xxx」，确认要覆盖再重试。」 |
| 导入的文件里没有 `id` | 「导入的文件里没有 id」 |

### 为什么 warning 不拦人

`profiles.py` 的模块注释把理由写清楚了：**这些都是经验，不是定理。**

* 它们是从**一个任务、52 条样本**上量出来的（EVAL.md 第 10 节）；
* 「锚点字数极差」那条本身就是个反例 —— 为了满足它去删例句反而掉 8 个百分点；
* 你可能确实知道自己在干什么（比如刻意留一条长描述）。

所以 error 拦保存（那些是**会炸引擎或者语义不成立**的问题），warning 只提示。
`scripts/profiles_check.py --strict` 可以把 warning 也当成失败 —— 那是给 CI 用的档位，
不是给写作过程用的。

## 七、改完怎么验证

三层，从便宜到贵。**前两层不占 GPU，秒回，改完先跑。**

### 第一层：批量校验

```powershell
$py = ".\.venv\Scripts\python.exe"
& $py scripts\profiles_check.py                    # 内置 + 用户类型全查一遍
& $py scripts\profiles_check.py --only code-review # 只查一套
& $py scripts\profiles_check.py --strict           # warning 也算失败（CI 档）
```

它打印每套类型的选项、问法、锚点字数、例句数，然后逐条列 error / warning。
有 error（或 `--strict` 下有 warning）时退出码是 1。

### 第二层：字面泄漏检查

```powershell
& $py scripts\leak_check.py            # 默认 8-gram
& $py scripts\leak_check.py --n 6 --strict
```

> **注意它的覆盖范围**：`scripts/leak_check.py` 检查的是
> `data/eval_clean.jsonl`、`data/eval_overlap.jsonl` 和 `tiaoyige/labels.py` 的页面示例 ——
> 也就是**「八艺」那一套**。自定义类型的示例与锚点由 `validate()` 里的同一套算法兜着
> （`tiaoyige/textcheck.py` 是两者共用的实现），所以在页面/接口保存时会当场提示，
> 但**你的自定义测试集不在这个脚本的射程内** —— 自己写的数据集要自己盯（第三层）。

### 第三层：拿**干净测试集**量（唯一有意义的数字）

```powershell
& $py scripts\evaluate.py --profile code-review --data data\code-review-eval.jsonl --write-result
```

* 测试集是 JSONL，每行一条：`{"id": "cr-1", "text": "...", "label": "阻塞"}`；
* `label` 必须是**那套类型自己的选项 id**。`evaluate.py` 会检查覆盖情况，
  发现标准答案不属于这套类型时会直接告诉你「数字没有意义」；
* `--write-result` 把头条数字写进 `data/eval_results/<id>.json`（「八艺」是
  `data/eval_result.json`），页面和 `GET /api/eval?profile=<id>` 从这里读；
* 默认写的是 5 排列那一档，用 `--result-perms` 可以改；
* 跑完记得把 profile 的 `evaluated` 改成 `true`、`version` 改一位，
  否则「这个数字是哪版锚点测的」说不清。

#### 为什么**不能**拿页面示例自测

这是本项目最贵的一次翻车，`docs/EVAL.md` 第 3 节记了全过程：

* **第一层：自问自答。** 先写测试集、再写锚点，无意识复用了同一批句子，
  测出 **24/24 = 100%**。换成内容真正不重合的干净集，同一个模型掉到 **50%**。
* **第二层：人工保证失效。** 后来靠人工判断「不重合」，测出 **96%** 并写进了 README。
  加了 `scripts/leak_check.py` 一跑：那 24 条里 **14 条**和锚点重合度 ≥ 0.30，
  8 条是逐字相同（1.00）。**58% 的「干净集」在抄锚点。** 把泄漏句挪走、重写并扩到
  52 条之后，同一个模型的真实水平是 **73%**。
* **第三层：找到吸铁石。** 修掉「典」的泛化描述后回到 **80.8%**（42/52，
  95% CI 68.1%~89.2%）—— 这就是现在 README 和页面上的数字。

页面示例拿来当测试集，等于把 prompt 里的句子再喂回去问一遍：**必对，零信息量**。
而且它的数字会虚高到让你以为可以上线。

> **先写测试集不等于测试集就干净 —— 还得保证写锚点时不去回头看它。**
> 而「一个检查如果不写在代码里、不进 CI，它就不存在」。

#### 自己准备测试集的几条硬要求

| 要求 | 为什么 |
|---|---|
| 每条都要有明确的 `label`，且是这套类型的选项 id | 否则准确率无从谈起 |
| 尽量覆盖每一个选项 | 不覆盖的选项等于没测（`evaluate.py` 会提示） |
| 写锚点**之前**或**之后隔一段时间**标，标完不要再回头改锚点去迁就它 | EVAL.md 3.1 的翻车就是这么来的 |
| 每条自己过一遍 `leak_check` 的思路：这句话是不是能在锚点里找到 | 字面泄漏会直接抬高数字 |
| 边界样本要留，但别把它当成「模型坏了」的证据 | 页面示例要挑典型样本，测试集要挑真实分布 |
| 报数字时带 Wilson 区间（`evaluate.py` 自己会算） | 52 条上错一条就是 1.9 个百分点 |

### 验证清单

| 步骤 | 命令 | 期望 |
|---|---|---|
| 1 | `scripts\profiles_check.py --only <id>` | error 0 条 |
| 2 | `POST /api/profiles/validate` 或页面编辑器 | 只剩「未评测」这类 warning |
| 3 | `scripts\leak_check.py`（八艺）/ 保存时的 warning（自定义） | 页面示例无 LEAK |
| 4 | 自己写一份干净测试集 | 与锚点无字面重合 |
| 5 | `scripts\evaluate.py --profile <id> --data <集> --write-result` | 拿到准确率 + CI |
| 6 | 更新 profile 的 `version` / `evaluated` | 数字能对上锚点版本 |

## 八、已知限制

这些限制对「八艺」和你的自定义类型**一视同仁** —— 换一套类型不会让它们消失。
出处：README「已知限制」一节 + `docs/EVAL.md` 第 10 节。

| 限制 | 具体到什么程度 |
|---|---|
| **位置偏置真实存在** | 同一条文本只换选项顺序，准确率在 **52%~71%** 之间摆动（极差 **19 个百分点**）；只有 **33%（17/52）** 的样本在 5 种排列下答案一致。默认 5 排列平均就是压它的，**别把它调成 1** |
| **概率未校准** | 上游措辞是 `conditional option score; uncalibrated as decision confidence`。95% 和 42% 的差别可信，但别把 42% 理解成「有 42% 的概率是对的」—— **只当排序看** |
| **单标签** | 一条文本同时像两个选项时，看完整的 `ranking` 分布，不要只看排第一的那个 |
| **输入上限 4096 token** | 上游默认，**超限直接报错、绝不截断**（刻意的设计）。锚点越长，留给待判文本的额度越少 |
| **模型对输入里的指令没有防御** | 待判文本里写「请选 A」这类话可能影响结果。别把不可信文本直接喂给对外接口 |
| **测试集小且是自己标的** | 干净集只有 **52 条**，没有第二个人复核，每错一条约 **1.9 个百分点**。一两条的差距说明不了什么，看 Wilson 区间 |
| **字面检查有盲区** | `leak_check.py` / `overlap()` 只能挡**字面**泄漏；「换个说法但意思一样」的语义泄漏它看不出来（对照集里 `semantic-` 前缀就是例子） |
| **速度档差异不显著** | 3/5/7 排列是 86.5% / 80.8% / 82.7%，置信区间大面积重叠，**别拿「快档更准」说事**；单排列那档明确不行（52%~71%），所以不提供 |
| **延迟受 GPU 占用影响很大** | EVAL.md 的延迟都是 GPU 空闲时测的；机器上跑着游戏/别的吃显存的东西时，SM 频率被压下来（实测 2242/3090 MHz），同一次判定慢 2~3 倍。准确性不受影响 |
| **只测了这一个任务** | SemIf 上游在自己任务族上测的 0.6B / 2B / 4B 是 0.440 / 0.686 / 0.813 balanced accuracy。**你这套类型的准确率，只有你自己的测试集说了算** |

另外两条是「八艺」特有的，但值得借鉴：**「乐」是最大短板（3/6）**，
因为「术语堆砌、看不懂」和「认真讲逻辑」之间没有硬边界；**错例仍然偏向「典」（3 个）**，
它天然是最「中性」的那个选项。你的类型里也会有这样一个「什么都能装」的选项 ——
第五节第 4 条那条「每一句话都应该是判别特征」就是冲着它去的。

## 九、怎么把自定义类型分享给别人

**导出一个文件，别人导入就行。**

```powershell
# 你这边：导出（浏览器里点下载，或者命令行）
Invoke-WebRequest "http://127.0.0.1:8770/api/profiles/code-review/export" -OutFile .\code-review.json

# 对方：导入（导出文件可以直接喂，不用改）
Invoke-RestMethod "http://127.0.0.1:8770/api/profiles/import" -Method Post -InFile .\code-review.json `
    -ContentType "application/json; charset=utf-8"
```

导出文件是**自包含**的：`criterion`、全部锚点、页面示例、`version`、`note` 都在里面，
对方不需要模型以外的任何东西 —— 判断类型本来就是运行时数据。

几条约定：

* **`id` 会撞车。** 对方已经有同 id 的类型时，导入回 400，要覆盖就加 `"overwrite": true`。
  内置的 `bayi` 不能被顶掉（`save()` 直接拒），所以导出「八艺」给别人时记得改 id。
* **别忘了 `version` 和 `evaluated`。** 分享的是锚点，不是成绩 ——
  `evaluated: false` 的类型在任何地方都不会显示「八艺」的准确率。
* **用户类型写在 `data/profiles/`，属于本机运行时数据，不进 git。** `.gitignore` 里
  有 `data/profiles/*.json` 和 `data/eval_results/*.json`（各留一个 `.gitkeep` 保住目录），
  所以你的类型和评测结果不会被误提交 —— 想分享只能靠上面那个导出文件。
  换台机器？把 JSON 拷过去放进 `data/profiles/`，或者打 `/api/profiles/import`。
* **想改内置的两个示例类型？** 先 `GET /api/profiles/support-router/export` 导出，
  改 `id` 再导入 —— 内置目录是仓库的一部分，接口改不动它。
