# 八艺 v4.0.0

**这一版最大的变化：「判什么」变成了可改的数据。**

在此之前，词表是写死在代码里的八个字。现在判断类型（词表、判定问法、页面示例）
是**运行时的数据** —— 页面上改完保存即生效，不用重训，也不用重启服务。

> 这份文件是 `.github/workflows/release.yml` 的发布说明来源。
> 下次发版请改它；不想手写就把文件删掉，Actions 会退回 `--generate-notes` 自动生成。

## 下载

| 平台 | 文件 | 说明 |
|---|---|---|
| Windows | `hlwby-4.0.0-win64.zip` | 解压后双击 **`一键启动.bat`** |
| Linux / macOS | `hlwby-4.0.0-linux.zip` | 解压后 `./start.sh` |

启动器会自己找 Python、建虚拟环境、装依赖、下基座模型、起服务并打开浏览器。
**第一次要下载几个 GB**（依赖 + 模型 4.3 GB），之后每次启动十几秒。

包里的 `release-manifest.json` 是每个文件的 sha256，可以拿来校验下载是否完整：

```powershell
python -c "import json,hashlib,pathlib;m=json.load(open('release-manifest.json',encoding='utf-8'));bad=[f['path'] for f in m['files'] if hashlib.sha256(pathlib.Path(f['path']).read_bytes()).hexdigest()!=f['sha256']];print('校验通过' if not bad else bad)"
```

**模型权重不在包里** —— 它是 Qwen 的 Apache-2.0 权重（4.3 GB），不该由本项目转分发，
GitHub Release 单文件也放不下。启动器会按 pinned revision 自己拉。

## 这一版新增了什么

### 1. 判断类型可以自定义（高度可自定义）

一套「判断类型」（profile）= 判定问法 + 若干选项（每个选项一段锚点描述）+ 页面示例。

* **页面上改**：`词表` 标签页，新建 / 选一套 / 改锚点 / 保存。选项 2~16 个。
* **改完不用重启**：锚点是推理时才读进 prompt 的，不写进任何权重。
* **未保存也能试判**：编辑器里改一句锚点，右边立刻能看到判定结果怎么变。
* **导入导出**：导出成 JSON 发给别人，对方导入即可。
* **内置三套**：`八艺`（默认，唯一评测过的）、`客服分流`、`内容处置`
  —— 后两套是**示例**，明确标着「未评测」。

改锚点时，**校验会把已知会翻车的写法当场报出来**（这些规则来自本项目的实测教训，
不是拍脑袋定的）：

| 会报什么 | 依据 |
|---|---|
| 描述里有「一段不长不短的普通论述」这类泛化短语 | 它几乎对任何文本都成立，实测删掉它准确率 **+7.7 个百分点** |
| 描述写成了关系式（「当对方辩论时」） | 实测只有 50%，改成描述文本形态后到 96% |
| 描述里提到别的选项名 | 会把概率漏给那个选项 |
| 描述里几乎没有例句 | 实测：给例句 96% vs 只写抽象定义 23% |
| 页面示例和锚点例句字面重合 | 自问自答，必做对，没有信息量 |

完整指南见 `docs/CUSTOMIZE.md`。

### 2. WebUI 重做

`web/` 拆成了多文件静态站点（ES 模块，**仍然没有构建步骤**），四个标签页：

* **判定** —— 粘评论、选类型、三档速度、批量模式（一行一条，导出 CSV/JSON）、
  本地历史、分享链接（`?t=...&auto=1` 打开就能看到同一次判定）
* **词表** —— 判断类型的增删改查，实时校验，能看到**模型实际读到的 payload**
* **评测** —— 这套类型的成绩从哪来、怎么自己量一遍、分选项成绩
* **设置** —— 服务与模型状态、深浅色、默认档位、API 示例

深/浅色主题、URL 路由（`#judge` / `#labels` / `#eval` / `#settings`）、`Ctrl`+`Enter` 判定。

### 3. 一键下载即用的 release 包

* `scripts/build_release.py` —— 打 zip，附 `release-manifest.json`（每文件 sha256），
  可重复构建（同样输入两次构建，manifest 完全一致）
* `一键启动.bat` / `start.sh` / `scripts/launch.ps1` —— 找 Python、建环境、
  装依赖（`-Mirror` 走清华源）、按显卡装 CUDA 版 torch、下模型
  （先官方、失败自动换 hf-mirror）、起服务、开浏览器
* `.github/workflows/release.yml` —— 打 tag 自动构建两个平台的包并发布

### 4. 三道新的自动检查

这个项目被「文档里的数字过期」坑过两次（首页挂着一个作废的准确率、
README 里同时写着两个不同的单元测试数量），所以把它们都变成可执行的检查：

* `scripts/profiles_check.py` —— 所有判断类型逐条过校验规则（含你自己加的）
* `scripts/docs_check.py` —— README 里的准确率 / 样本量 / 测试数量必须等于代码里的真实值；
  项目结构里列的每个文件都得存在，新文件也得登记
* `scripts/page_check.py` —— 升级成多文件版：JS 里 `$("x")` 引用的 id 必须在 HTML 里存在，
  少一个就是运行时崩溃，静态检查提前抓

## 数字

* 干净测试集 **52 条实测 80.8%**（5 排列，95% CI 68.1%~89.2%），页面示例 8/8。
* 三档速度：3 排列 86.5% / 5 排列 80.8% / 7 排列 82.7% —— **差异不显著**，
  置信区间大面积重叠，别把「快档更准」当结论。
* 这一版**重跑过完整评测**，三个档位的准确率和 v3 完全一致（42/52、45/52、43/52），
  说明把词表抽成 profile 没有改变判定结果。

数字的唯一出处是 `data/eval_result.json`，页面上所有准确率都从 `GET /api/eval` 读，
`scripts/docs_check.py` 会盯着它和 README 一致。

## 已知限制（没有变）

* 概率**未校准**，只能当排序看，不能当「模型有多确定」。
* 位置偏置真实存在：换选项顺序答案会变，只有 33% 的样本在 5 种排列下答案一致。
  所以别把排列数调成 1。
* 「乐」是最弱的选项（3/6）；错例仍然偏向「典」。
* 输入上限 4096 token，超限直接报错，**不截断**。
* 模型对输入里的指令没有防御。
* 测试集只有 52 条、自己标的、没有第二个人复核 —— 看置信区间，别看小数点。
* **自定义类型默认没有评测数字**，页面上会显示「未评测」。那不是「不好用」，
  是「没人量过」；别把「八艺」的成绩算到别的类型头上。
