# 帮你挑一个 v4.2.0

给它一段文本、再给它一组**你自己定的选项**，它帮你挑一个。这个包解压就能用。

> 这份文件是 `.github/workflows/release.yml` 的发布说明来源（会作为 GitHub Release 的正文）。
> 下次发版请改它；不想手写就把文件删掉，Actions 会退回 `--generate-notes` 自动生成。

---

## 快速开始

| 平台 | 文件 | 怎么做 |
|---|---|---|
| Windows | `tiaoyige-4.2.0-win64.zip` | 解压，双击 **`一键启动.bat`** |
| Linux / macOS | `tiaoyige-4.2.0-linux.zip` | 解压，`./start.sh` |

启动器自己做完这五件事，每步都打印中文进度：

1. 找 Python（要 3.10 或更高；没有会告诉你去哪装）
2. 建 `.venv`、装依赖
3. 有 NVIDIA 显卡就装 CUDA 版 torch，没有就按 CPU 跑
4. 下载基座模型（Qwen3.5-2B，约 4.3 GB）
5. 起服务、打开浏览器 → <http://127.0.0.1:8770/>

第一次要下载几个 GB，**别关窗口**；之后每次启动十几秒。在那个窗口按 `Ctrl+C` 停。

常用参数（Windows 上是 `一键启动.bat -Mirror`，Linux/macOS 是 `./start.sh --mirror`）：

| 参数 | 什么时候用 |
|---|---|
| `-Mirror` | 装依赖太慢 / 超时（走清华 TUNA 源） |
| `-HfMirror` | 连不上 huggingface.co（直接走 hf-mirror，少等一次超时） |
| `-Port 8771` | 8770 被占用 |
| `-Model qwen3-0.6b` | 想更小更快，或显存不够 |
| `-Device cpu` | 没有 NVIDIA 显卡 / 想强制用 CPU |
| `-NoBrowser` | 不想自动开浏览器 |

> **模型权重不在包里** —— 它是 Qwen 的 Apache-2.0 权重（4.3 GB），不该由本项目转分发，
> GitHub Release 单文件也放不下。启动器会按 pinned revision 自己拉。

包里的 `release-manifest.json` 是每个文件的 sha256，可以校验下载是否完整：

```powershell
python -c "import json,hashlib,pathlib;m=json.load(open('release-manifest.json',encoding='utf-8'));bad=[f['path'] for f in m['files'] if hashlib.sha256(pathlib.Path(f['path']).read_bytes()).hexdigest()!=f['sha256']];print('校验通过' if not bad else bad)"
```

## 这个工具是什么

模型**不生成文字**：每个选项绑到一个单字母槽位，一次前向传播读出概率，所以小模型也能半秒出结果。
**判定标准（锚点）是运行时的数据** —— 页面上就能改，改完不用重训、不用重启。

内置的词表是网络梗「八艺」：典 孝 急 乐 蚌 批 赢 麻。
也可以完全不用它 —— 换成审核分流、工单分类、内容处置、情绪打标，随便什么，只要能写成一组选项。

页面上四个标签页：

| 标签页 | 干什么 |
|---|---|
| **判定** | 粘文本 → 选类型 → 出概率分布；支持批量（一行一条，导出 CSV/JSON）、历史、分享链接 |
| **词表** | 改判断类型：判定问法、每个选项的锚点描述、页面示例；实时校验；**没保存也能试判** |
| **评测** | 这套类型的成绩、置信区间、分选项成绩 |
| **设置** | 服务与模型状态、深浅色、默认档位、导出类型 |

## 自己定一套判断类型

`词表` 标签页 → 新建 → 改锚点 → 保存。**改完不用重启，判定页立刻生效。**

写锚点记住这几条（每条都有实测依据，细节见包里的 `docs/EVAL.md`）：

* **描述「文本长什么样」，不要描述「说话人在干什么」**（关系式写法实测只有 50%，改成描述文本形态后到 96%）
* **给例句，别写抽象定义**（多锚点 96% vs 长抽象定义 23%）
* **别在描述里提别的选项名**（概率会漏给那个选项）
* **别写「一段不长不短的普通论述」这类泛化短语**（会把概率全吸过去，实测删掉它 +7.7 个百分点）
* **页面示例别抄锚点例句**（那是自问自答，必对，没有信息量）

页面上的实时校验就是这些规则；命令行对应 `scripts/profiles_check.py`。
完整指南见 `docs/CUSTOMIZE.md`。

**别拿页面示例自测准确率。** 要量就另准备一份干净测试集（JSONL，每行 `{"id","text","label"}`），
跑 `scripts/evaluate.py --profile <id> --data <测试集> --write-result`。

## 数字

* 内置「八艺」：干净测试集 **52 条实测 80.8%**（5 排列，95% CI 68.1%~89.2%），页面示例 8/8。
* 三档速度：3 排列 86.5% / 5 排列 80.8% / 7 排列 82.7% —— **差异不显著**，置信区间大面积重叠，
  别把「快档更准」当结论。
* 页面上的准确率只有一个出处（`data/eval_result.json` → `GET /api/eval`），不写在页面里；
  `scripts/docs_check.py` 会盯着它和 README 一致。

自定义类型默认**没有**评测数字，页面上会显示「未评测」—— 那不是「不好用」，是「没人量过」。

## 已知限制

* **概率未校准**，只能当排序看，不能当「模型有多确定」。
* **位置偏置真实存在**：换选项顺序答案会变，只有 33% 的样本在 5 种排列下答案一致。
  所以别把排列数调成 1。
* 内置「八艺」里 **「乐」最弱**（3/6），错例仍然偏向「典」。
* **输入上限 4096 token**，超限直接报错，**不截断**。
* 模型对输入里的指令没有防御。
* 测试集只有 52 条、自己标的、没有第二个人复核 —— 看置信区间，别看小数点。
