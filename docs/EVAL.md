# 评测记录：八艺（典孝急乐蚌批赢麻）

这份文档记录**实际测出来的数字**，包括失败的尝试和翻车的过程。所有结论都可以用仓库里的脚本复现。

硬件：RTX 5070 Ti Laptop（12 GB，sm_120）· torch 2.14.0+cu130 · bfloat16 · Windows。

> **延迟数字有个前提**：下面标的时间都是在 GPU 空闲时测的。机器上跑着游戏 / 别的
> 吃显存的东西时，SM 频率会被压下来（实测 2242/3090 MHz），同一次判定会慢 2~3 倍。
> 准确性不受影响，只是变慢。

## 1. 最终结果

**干净测试集 52 条：42/52 = 80.8%**（默认 5 排列，Wilson 95% CI 68.1%~89.2%）。

| 排列数 | 准确率 | 95% CI | 端到端中位 |
|---:|---:|---|---:|
| 3 | 86.5%（45/52） | 74.7%~93.3% | ~0.32 s |
| **5（默认）** | **80.8%（42/52）** | **68.1%~89.2%** | **~0.53 s** |
| 7 | 82.7%（43/52） | 70.3%~90.6% | ~0.73 s |

> **三档之间的差异不显著。** 52 条样本上 86.5% 和 80.8% 只差 3 条，
> 置信区间大面积重叠。**不要得出「快档更准」的结论** —— 那是噪声。
> 单排列那一档倒是明确不行（52%~71%，见第 5 节），所以页面上不提供。

页面示例（8 条，每个词一条）：**8/8**。

### 分标签（干净集，5 排列）

```
典 6/7   孝 6/7   急 4/6   乐 3/6   蚌 7/7   批 6/6   赢 6/6   麻 4/7
```

* **「乐」是最大短板（3/6）。**「术语堆砌、看不懂」和「认真讲逻辑」之间没有硬边界 ——
  两者都是长而抽象的文字。它输的时候往往不是排第二，而是根本没有竞争力。
* **「急」掉到 4/6**，两个错例都判成了「蚌」。这两句都是「一条条说」式的列举，
  和「逼你表态」在表面形式上确实接近。
* **错例仍然偏向「典」（3 个）**，但比修之前（10 个）好很多，见第 3.3 节。

## 2. 评测集

| 文件 | 条数 | 用途 |
|---|---:|---|
| **`data/eval_clean.jsonl`** | **52** | **干净集。`scripts/leak_check.py` 验证过与锚点无字面重合。以这套为准。** |
| `data/eval_overlap.jsonl` | 39 | 对照集。页面示例的三个变体 + **从干净集里揪出来的泄漏句**。别拿它的数字当结论。 |

### id 命名规则

两套集子原来都叫 `dian-1`…`ma-3`，但文本完全不同 —— 合并分析时会静默串味。
现在分前缀：

| 前缀 | 含义 |
|---|---|
| 无前缀（`dian-1`） | 干净集 |
| `ov-` | 页面示例的变体（原本就存在，不是泄漏） |
| `leaked-` | **字面泄漏**：和锚点例句重合度 ≥ 0.30，多数是 1.00 |
| `semantic-` | **语义泄漏**：意思和锚点一样但换了说法，字面检查抓不到 |

`leaked-` 和 `semantic-` 的区别很重要 —— 它标出了 `leak_check.py` 的**已知盲区**。
`tests/test_labels.py` 里有对应的测试把这两类钉住。

```powershell
& $py scripts\evaluate.py --perms 3,5,7
& $py scripts\leak_check.py
```

## 3. 三次翻车

这一节是这份文档里最该看的部分。三次都是**同一个毛病**：拿一个不干净的尺子量自己。

### 3.1 第一次：自问自答，测出 100%

这一版**第一次测出来是 24/24 = 100%**。这个数字是假的。

原因：我先写了测试集，再写锚点，结果无意识地复用了同一批句子。例如

- 测试 `dian-1`：「说到底还是教育的问题，现在的家长只顾着赚钱」（28 字）
- 锚点例句：「说到底还是教育的问题，现在的家长只顾赚钱不管孩子」

几乎是同一句话。换成内容**真正不重合**的干净集之后，同一个模型掉到 **50%**。

> **先写测试集不等于测试集就干净 —— 还得保证写锚点时不去回头看它。**

### 3.2 第二次：人工保证失效，96% 也是假的

后来建了 `data/eval_clean.jsonl`，靠**人工**判断它和锚点不重合，测出 **96%**，
写进了 README 和介绍视频。

问题在于：**锚点后来又改过几版**（现在是 `meme-direct-zh-v4`），
而「人工保证不重合」这件事没有任何机制兜着。

于是加了 `scripts/leak_check.py`：两边都去掉标点、只留中英文数字，
比字符 n-gram 的重合率（分母取较短一侧，否则长描述天然占便宜）。
一跑就发现那 24 条里有 **14 条**中招：

| 测试集 id | 句子 | 重合度 |
|---|---|---:|
| `beng-1` | 说了这么多，那你倒是给个解决方案啊。 | 1.00 |
| `pi-1` | 追星的都是脑残，这点没什么好争的。 | 1.00 |
| `pi-3` | 玩游戏就是不务正业，不管你怎么解释都一样。 | 1.00 |
| `ying-1` | 成年人的崩溃，都是从缺钱开始的。 | 1.00 |
| `ying-2` | 所谓成熟，就是把哭声调成静音的过程。 | 1.00 |
| `ying-3` | 真正厉害的人，从来都不动声色。 | 1.00 |
| `ma-2` | 嗯嗯，受教了。 | 1.00 |
| `le-1` | 这件事的本质是能指与所指的断裂，是符号系统自我指涉的必然结果。 | 0.82 |
| `xiao-1` | 苹果的生态就是比安卓好用，用过就知道了，别不服气。 | 0.73 |
| `dian-3` | 这事不能全怪孩子，主要还是从小没教好，家庭教育才是根子。 | 0.56 |
| `ji-1` | 我们先明确一个前提：如果这个假设不成立，后面的推论就全都站不住…… | 0.55 |
| `le-3` | 你要辩证地看，矛盾的主要方面和次要方面在不同阶段是会相互转化的。 | 0.48 |
| `ji-2` | 你这个说法有三个漏洞。第一，样本量太小；第二，没有对照组…… | 0.32 |
| `ma-3` | 那可能是我理解错了，打扰了。（语义泄漏，字面 0.0） | — |

**14/24 = 58% 的「干净集」在抄锚点。** 这 14 条已经挪进对照集（前缀 `leaked-`），
干净集重写并扩到 52 条。重测之后，同一个模型的真实水平是 **73%**（5 排列）。

> **一个检查如果不写在代码里、不进 CI，它就不存在。** 「我记得我检查过了」
> 挡不住锚点被改第四版。

### 3.3 第三次：找到那个「吸铁石」

在 52 条干净集上重测之后，错例长这样：

```
ji-2:急->典   ji-4:急->典   le-1:乐->典   le-2:乐->典
le-5:乐->典   pi-4:批->典   ying-2:赢->典 ma-2:麻->典 ...
```

**14 个错例里 11 个判成了「典」**，而且跨了 5 个不同的标准答案。
一个词把别人全吃掉，说明它不是判得准，是**描述太泛**：

> 「这段话在讲道理、分析原因、下判断 —— **一段不长不短的普通论述**。」

后半句几乎对所有中文评论都成立 —— 它不是判别特征，是吸铁石。

`scripts/anchor_tune.py` 只改这一段措辞、其余七个字不动，做了剂量反应：

| 「典」的描述 | 准确率 | 95% CI | 判成「典」的错例 |
|---|---:|---|---:|
| 换成**更泛**的说法 | 69.2% | 55.7%~80.1% | **15** |
| **原来（带那句）** | **73.1%** | 59.7%~83.2% | **10** |
| 只删掉那句 | **80.8%** | 68.1%~89.2% | **3** |
| 再窄一档（只讲「解释成因/下结论」） | 76.9% | 63.9%~86.3% | 3 |

**单调关系是这件事最有力的证据**：描述越泛，吸得越狠。
单看「73.1% → 80.8%」只是 4 条，落在噪声范围内；
但「越泛 → 吸得越多」这个方向不可能由噪声产生。

所以采用了「只删掉那句」这一档：**73.1% → 80.8%**。

> 这条经验可以推广：**锚点里的每一句话都应该是判别特征。**
> 如果一句话对「不属于这个词」的样本也成立，它就在偷概率。

## 4. 锚点怎么写（六条实测结论）

### 4.1 描述「文本长什么样」，不是「说话人在干什么」

**这条最重要，也是最反直觉的。**

这套定义是关系式的（「当对方辩论时，说急」）。我最初照字面写锚点：
「对方在跟你辩论，或者开始细致地解说……」—— 结果**全部塌缩到「赢」**。

对照实验（`scripts/experiment.py --variants relational`）：把同一个意思分别写成
格言腔和大白话：

| 形式 | 文本 | 期望 | 判成 |
|---|---|---|---|
| 格言腔 | 人最大的敌人，从来都是自己。 | 赢 | **赢 99%** ✅ |
| 大白话 | 我觉得人最大的问题就是过不了自己那关。 | 典 | **赢 91%** ❌ |

大白话版本完全不是格言，却被判成赢。说明模型没在按定义判。

**修法**：把描述改成描述**文本的表面形态** ——

- 「急」=「逐条辩论、分点回击，常见开头是『第一……第二……第三』」
- 「赢」=「对仗、押韵、格言腔，『不是……而是……』『从来都是』」
- 「麻」=「只有一句敷衍的附和，非常短」

改完 **50% → 79% → 96%**。

> **2B 模型做的是表面形式匹配，不是关系推理。锚点要写「这段文本长什么样」，
> 而不是「说话人在干什么」。**

### 4.2 给例句，别写抽象定义

| 写法 | 结果 |
|---|---:|
| 长描述（3~4 句抽象定义） | 23% |
| 只给关键词 | 1/10 |
| **多锚点例句** | **当前方案** |

抽象定义要求概念推理，例句只要求模式匹配 —— 后者才是 2B 模型擅长的事。

```powershell
& $py scripts\experiment.py --variants shipped,short,keyword,relational
```

### 4.3 要示范，不要解释

诊断出模型老把「内容里有人在放弃」读成别的词，于是我在每段描述后加了
「区别：这不是 X，那是 Y」。**结果从 83% 掉到 73%。**

原因：描述里提到别的词名，会把概率质量漏给那些词 —— 十段里八段都写了同一个词名，
那个词就被反复激活成了吸铁石。

### 4.4 别写泛化的形状描述（新增，见第 3.3 节）

「一段不长不短的普通论述」这种话对任何中文评论都成立，会把概率全吸过去。
删掉它，52 条上 **+7.7 个百分点**，判成「典」的错例从 10 个降到 3 个。

```powershell
& $py scripts\anchor_tune.py
```

### 4.5 别为了长度好看去删例句

`labels_check.py` 会警告描述长度极差过大。我一度为了把它压到阈值内删了几条锚点例句，
**准确率立刻从 96% 掉到 88%**。恢复例句后回到 96%。

所以那条阈值改成了**软警告**：长度失衡只是略微放大位置偏置（而排列平均已经在压它），
锚点数量才是准确率的主要来源。

### 4.6 页面示例要挑典型样本，而且不能抄锚点

有个尴尬的发现：干净集 96%，但**页面上的示例自己只判对 6/8** ——
其中「乐」的示例被判成「典」（39%）。看上去像模型坏了。

一查不是：把**每个词的锚点例句单独拿出来判，8/8 全对**。
问题出在挑的页面示例 ——「基于量子纠缠的非定域性……」虽然是术语堆砌，
但模型觉得它更像「典」（陈述了一个观点）。换成更典型的一句之后 8/8。

**但 8/8 一度也是假的。** 后来 `leak_check.py` 发现两个页面示例直接抄了锚点：

| 页面示例 | 和锚点的重合度 |
|---|---:|
| 「那可能是我理解偏了，打扰了。」 | **1.00**（锚点里一字不差） |
| 「这个问题的关键在于主体间性的建构……再生产。」 | 0.27（等于把锚点例句改了两个字） |

两处都换掉了，现在 8/8 是**真的** 8/8。

> **展示用的例子要挑该词的典型样本，但不能是 prompt 里的句子。**
> 测试集可以有边界样本，但页面示例如果本身是边界样本、或者是抄来的，
> 会让人误以为系统坏了 —— 或者误以为它很好。

## 5. 位置偏置：这个引擎最大的坑

读法是「看模型下一个 token 是哪个字母」，而**模型对字母位置本身有偏好**。
同一条文本、同一个模型，只换选项顺序（`scripts/order_bias.py`，52 条）：

| 选项顺序 | 准确率 |
|---|---:|
| 原始顺序 | 71%（37/52） |
| 完全反转 | 60%（31/52） |
| 随机排列 1 | 67%（35/52） |
| 随机排列 2 | 62%（32/52） |
| 随机排列 3 | 52%（27/52） |

* **极差 10 条 = 19 个百分点** —— 纯粹是字母位置噪声，与语义无关。
* **只有 33%（17/52）的样本在 5 种排列下给出同一个答案。** 剩下 35 条的结果
  取决于选项怎么排。
* **5 排列取平均：42/52 = 81%**，比任何一个单排列都好。

> **⚠️ 这组数字修正过一次。** 之前 README 写的是「极差 16.7 个百分点、
> 67% 稳定」，再之前（十词版）写的是「8% 稳定」。都不对。
>
> 原因是 `scripts/order_bias.py` 有个 bug：它调 `engine.choose()` 时**没传
> `permutations=1`**，于是每一种「单排列」其实都被 `choose()` 按默认值又展开了
> 5 种排列取平均 —— 量出来的极差和稳定性全是假的。
>
> 发现方式是拿它和另一个独立实现（介绍视频项目里的 `bias_probe.py`，
> 那个脚本显式传了 `permutations=1`）对数字，两个脚本对不上。修完之后两边
> **逐条一致**（37/31/35/32/27），这本身就是一次交叉验证。
>
> **两个独立实现量同一个东西，是一个便宜的 bug 探测器。**

### 解法：多种排列取平均（并成一个 batch）

同一段文本配 N 种排列各判一次，按标签 id 平均概率。因为**所有排列共享同一段文本**，
只有末尾选项列表不同，所以左填充塞进**一个 batch** 跑，不是跑 N 次。

批量只快约 1.4x（2B 模型在 batch 下是显存带宽瓶颈），但相比串行仍然划算：

```
串行 7 次:  866 ms
批量 1 次:  623 ms   -> 快 1.4x
```

固定 seed，所以同一个输入永远得到同一个答案。

### 别提供单排列这一档

单排列会塌缩到描述最长、位置占便宜的那个词，52 条上只有 **52%~71%**。
所以页面上最低档是 3 个排列。**这不是性能取舍，是正确性问题。**

### 长输入自动降档

prompt 本身就不短：八个词的锚点加起来约 950 token，
**哪怕评论只有一句话，prompt 也有 1000 token 左右**。
按「评论长度」估预算会把默认档悄悄压成更少的排列（这个 bug 我犯过一次）。

最终 `TOKEN_BUDGET = 7500`：

| 输入 | prompt token | 快/标准/更稳 实际排列数 |
|---|---:|---|
| 一句话评论 | ~1000 | 3 / 5 / 7 |
| 长评论 | ~2000 | 3 / 3 / 3 |
| 长文 | ~3400 | 2 / 2 / 2 |
| 接近上限 | 4000+ | 1 / 1 / 1 |

## 6. 问法：影响不大

同一套描述，换 criterion：

| 问法 | 准确率 |
|---|---|
| `bayi`：下面这句网上的发言，最符合「八艺」里的哪一个？ | 当前方案 |
| `abstract`：这段发言最主要体现哪种心态/姿态/场面？ | 接近 |
| `danmu`：只能回一个字，像发弹幕那样，你发哪个？ | 接近 |

选了 `bayi`，因为它最贴近实际用法。

> 注意：在早期那套**书面语料**上，`danmu` 曾经明显更差（57% vs 63%），
> 因为它会让模型过度预测「典」。换成语料之后这个差距消失了。

## 8. 被否掉的其它方案

### 8.1 「是/否」二选一（Noul 原语）—— 完全饱和

每个词单独问「这段话是否体现了『X』？」。**八个词全部拿到 100% 的 p(符合)**，
0.6B 和 2B 都一样。小模型在这种绝对判断上一律回答「是」。准确率接近随机。

### 8.2 四档有序打分（Score 原语）—— 不饱和，但没区分度

各个词的合成分**全部落在 70~78% 的窄带里**，而且慢 6 倍。

**所以最终只保留单选。** 完整概率分布本身就能看出「同时像好几个字」。

### 8.3 十词版「经典版」—— 已删除

早期还做过一套 10 个字的版本（典孝急乐绷赢麻润摆寄，按「这段话是什么心态/场面」判）。
两套并存过一段时间，后来按用户要求只保留八艺，经典版连同它的三套测试集、
`evaluate_profile.py`、`debug_le.py` 一起删掉了。

它的实测数字（干净集 90%）留在提交历史里 —— 但**那个 90% 同样没有经过
`leak_check.py` 检查**，所以也未必成立。

## 10. 这套数字的局限

* **样本还是小**：52 条，每错一条就是约 1.9 个百分点。
  「从 50% 到 96%」「从 73% 到 81%」这种幅度可信；
  一两条的差距**说明不了什么** —— 所以现在一律附 Wilson 95% 区间。
* **有说服力的只有三组**，因为都是同一条文本自己跟自己比、或者只动一个变量：
  1. 位置偏置（19 个百分点极差、33% 稳定）；
  2. 格言腔 / 大白话对照（同一意思换个说法，判定从典掉到赢）；
  3. 「典」描述的剂量反应（越泛吸得越多）。
* **标签是我自己标的**，没有第二个人复核。这套定义本来就模糊 ——
  「乐」到底是「看不懂」还是「觉得好笑」，网上两种用法都有，我按「看不懂」实现。
  这类分歧换个人标可能结论不同。
* **`leak_check.py` 只能挡字面泄漏。** 语义上「换了个说法但意思一样」的泄漏
  它看不出来（对照集里 `semantic-` 前缀的行就是例子）。
  那部分只能靠写锚点时不去看测试集 —— 而这正是第 3.1 节翻车的原因。
* **只测了这一个任务**。SemIf 上游在自己任务族上测的 0.6B / 2B / 4B 分别是
  0.440 / 0.686 / 0.813 balanced accuracy。
* **概率不是校准过的置信度**。上游原话是
  `conditional option score; uncalibrated as decision confidence`。
  页面上 95% 和 42% 的差别可信，但别把 42% 理解成「有 42% 的概率是对的」。
